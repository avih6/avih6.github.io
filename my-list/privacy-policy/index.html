1. Overview & Privacy-First Principle

The "My List" application (the "App") is developed and maintained by avih6 as a utility application. This SERVICE is provided at no cost and is intended for use "AS IS".

This Privacy Policy explains how information is handled, stored, and protected during the use of the My List mobile application and its associated web pages. The application follows a privacy-first approach: lists stay on the device unless a user explicitly shares a list. Signing in with Google alone does not upload local-only lists. When a list is shared, its content is stored in Firestore and synchronized for its members. The App does not currently display ads, sell personal information, or use personal information for advertising.

By downloading or using the Service, the user agrees to the collection and use of information in accordance with this policy.

2. Data Handling, Storage & Synchronization

2.1 Local Offline Storage (Default)

Local-only lists and their items are stored in the application's private database and settings storage on the device. They are not sent to Firestore unless the user explicitly chooses to share that list. Removing the App or clearing its data can remove local-only lists; they are not available to other devices.

2.2 Sharing & Cloud Synchronization

A list is uploaded to Firestore only after the user explicitly shares it. Signing in with Google does not upload lists that remain local. Once shared, the list synchronizes for its members and may be available on their devices:

  • Shared-list data: List names and item names, quantities, units, optional notes, categories, checked states, and timestamps are stored in Google Cloud Firestore. Member names and identifiers, appointed admin roles, invite-code metadata, and list settings are also stored to provide collaboration.
  • Invite codes and previews: Shared lists use a randomly generated invite code. A preview page shows the list name and current member names before joining. Any authenticated user with a valid code may request to join, after which the list and its items are available to that member. The current app and Firestore rules limit a list to 100 members.
  • Authentication: Google sign-in provides the account display name, email address, and Firebase user identifier needed for sign-in and list membership. Guest accounts use a Firebase user identifier without requiring a Google account. Account passwords are never accessible to the App.
  • Optional profile photos: A Google profile photo is added to a particular shared list only after the joining user explicitly enables sharing for that list. Google sign-in does not enable photo sharing by itself.
  • Activity details: A shared list may display who added an item and when. The list creator controls this setting. Item contributor names and timestamps are stored with shared items.
  • Notifications: Firebase Cloud Messaging may deliver notifications when an item is added to a shared list or marked as purchased, based on separate per-list preferences. The Firebase user record can store the device messaging token. Notification text does not include list item names.
  • Making a list private: The list creator can save a local copy of the shared list and its items on the current device, then remove the shared list and invite code for all members. The resulting copy remains local to that device unless it is shared again.
  • Anonymous Guest Mode: Users can collaborate anonymously without providing an email address or real name.

3. Third-Party Services & Technical Data Collection

3.1 Technical Identifiers & Analytics

To ensure app stability, monitor performance, and improve user experience, the app incorporates reputable industry-standard SDKs provided by Google LLC:

  • Google Analytics for Firebase: Collects aggregated, non-personally identifiable usage statistics (such as screen views and feature engagement). Firebase automatically derives coarse geographic data from IP addresses on Google servers without accessing device GPS. This aggregated data is completely separate from any Google Sign-In user account.
  • Firebase Crashlytics & Performance Monitoring: Automatically collects crash logs, stack traces, and device hardware/OS specifications to troubleshoot and fix technical issues.

5. User Rights, Data Control & Deletion

Available controls depend on whether a list is local or shared:

  1. List and item controls: Users can edit or clear items in accordance with the list permissions. A local list can be deleted from the device. The creator can delete a shared list for everyone, or make it private by saving a local copy before removing the shared version and invite code.
  2. Leaving a shared list: A member can leave while at least two members remain. If the creator leaves, ownership passes first to the first remaining admin in the order appointed; if none remain, it passes to the first remaining member. The former creator loses access and needs a new invitation to rejoin. The last remaining member cannot leave an empty group; the creator can instead delete it or make it private. Users can also sign out or request account removal through App Settings.
  3. Manual Deletion Request & Partial Data Deletion: Users may also submit a request to delete specific shopping lists, shared groups, or particular data records without requiring the deletion of their entire account by emailing av6development@gmail.com. To prevent unauthorized deletions and protect user privacy, the deletion request must be sent directly from the specific Google account email address associated with the records to be deleted. If no confirmation is received, please send a reminder email with "Data Deletion Reminder" in the subject line.
  4. Technical diagnostics and usage metrics: Firebase Analytics, Crashlytics, and Performance Monitoring may collect pseudonymous app-instance identifiers, feature-use events, crash reports, stack traces, and device or operating-system details. The App does not set the Google sign-in UID as the Analytics user ID. Deleting an account or list in the App does not itself erase technical telemetry already held by Google; provider retention practices apply.

6. Data Security

Security of user information is prioritized, and commercially reasonable technical and organizational safeguards are employed. All data in transit is encrypted using modern TLS/HTTPS protocols. However, no method of electronic storage or internet transmission is 100% immune to vulnerabilities, and absolute security cannot be guaranteed.

7. Children's Privacy

If it is discovered that a child under 13 has provided personal data, please send a notification immediately to the contact email so that the information can be promptly removed.
